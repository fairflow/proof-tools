## (iv) What differed

1. **From the plan.**
   * S2 is PROVED in this stage; the plan left it to be stated.
   * `within` is equality of set sequents (`sameSet`, written for K°),
     not a test special to `◇k_c`. For system K it sets aside the same
     moves.
   * The plan's Q4 asks for a sequent "on request as its tree". Not
     done: a goal is shown in brackets only.
2. **From the source.** No divergence beyond D1 to D14 of the signed
   table. Two things of the proof system that the source has no word
   for: a move names its node by a path of positions, and the axiom's
   move carries the number of the proposition (`ax [0] 4` for `a, ā` in
   the first box).
3. **From the skill** (`method-notes.md`, notes 26 to 34). In brief: the
   template's form of S1 does not fit a rule that first looks its node
   up by a function, and a second function (the rule, given the node)
   was needed; `decide +kernel` on `S.step m j = .ok ps` has no
   `Decidable` instance in core Lean, so the kernel checks compare
   through `.toOption`; an exercise whose first query is an error cannot
   have that query written, if the file is to elaborate; a tactic's name
   becomes a keyword, so it cannot be a letter.
4. **Asked of the library**: nothing. `apply_move` names a place inside
   a sequent with no change: a path is an argument of the move like any
   other, and patterns fill it.
